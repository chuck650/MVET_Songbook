# Music Notation & Typography Standards Rule

## Objective
Preserve musical integrity and typographic correctness across the MVET Songbook codebase, metadata manifests, user interfaces, documentation, and agent responses.

---

## 🎼 Mandatory Accidental Symbols

**NEVER use ASCII letters or regular typographic symbols as substitutes for music notation.**
In particular, never use lowercase `b` for flat, the hash/pound symbol `#` for sharp, or the letter `h`/`n` for natural.

Always use their official Unicode equivalents:

| Musical Element | Unicode Character | Codepoint | Standard Representation | Forbidden Substitutes |
|:---|:---:|:---:|:---|:---|
| **Flat** | `♭` | `U+266D` | `B♭ major`, `E♭`, `A♭` | `Bb`, `Eb`, `Ab`, `B-flat` |
| **Sharp** | `♯` | `U+266F` | `F♯ minor`, `C♯`, `G♯` | `F#`, `C#`, `G#`, `F-sharp` |
| **Natural** | `♮` | `U+266E` | `B♮`, `F♮` | `Bn`, `B natural`, `B` |

---

## Scope & Applicability

This rule applies universally across:
1. **Song Metadata**: All `metadata.json`, `song.json`, and `songs.json` catalog entries (e.g. `"key": "B♭ major"`, `"key": "F♯ minor"`).
2. **Score Rendering & UI**: Key badges, part labels, titles, dialogs, and rehearsal tooltips in React components and CSS text.
3. **Manifest Generation Tools**: Manifest scripts (`scripts/generate-manifest.cjs`) and parsers extracting or normalizing key signatures from MusicXML or MSCZ.
4. **Documentation & Specifications**: OpenSpec documents, user guides, READMEs, and changelogs.
5. **Agent Responses**: All conversation text, plan artifacts, walkthrough summaries, and commit messages generated by AI agents.
